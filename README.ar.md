لوحة بأسلوب «مركز استخبارات الهاكرز» تعمل على Cloudflare Workers: تفحص مستودعات GitHub الرائجة وفق جدول زمني، وتستخدم **محرك قواعد** (وليس ذكاءً اصطناعياً) لتقييم الشعبية ووضع وسوم نقاط التعلم، لتخبرك أيّ المشاريع مفتوحة المصدر تتصاعد في الآونة الأخيرة، وما الذي يستحق التعلم من كلٍّ منها. ويُدفَع «الموجز الرئاسي» كل صباح تلقائياً إلى محادثتك الخاصة في Telegram وقناتك (تُسجَّل القناة تلقائياً بمجرد جعل البوت مشرفاً فيها، دون أي إعداد).

ملف واحد `worker.js`، بلا أي تبعيات، والبيانات مخزّنة في KV. لوحة داكنة: خلفية شبه سوداء + أخضر/سماوي نيون + خط أحادي المسافة + ملمس خطوط مسح + شريط متحرك.

## الميزات

- **إحدى عشرة قناة استخباراتية** (أضاف v2 ثلاثاً، وأضاف v3 اثنتين أخريين؛ كل جولة فحص تجري 11 استدعاءً لواجهة GitHub Search API، وهو أقل بكثير من حدّ الخطة المجانية البالغ 50 طلباً فرعياً)
  1. `surge` النجوم الصاعدة بسرعة: أُنشئت خلال آخر 30 يوماً، stars>50
  2. `trending-week` رائجة هذا الأسبوع: دُفعت خلال آخر 7 أيام، stars>5000، من المشاريع العريقة الرائجة
  3. `ai-agent` ‏AI/AGENT: الكلمات المفتاحية ai-agent / llm / mcp
  4. `workers` الحافة/Bot: ‏cloudflare-workers / serverless / telegram-bot
  5. `media` توليد الوسائط المتعددة: comfyui / image-generation / text-to-speech
  6. `devtools` أدوات التطوير: developer-tools / browser-automation / playwright
  7. `security` أمن الشبكات · الفريق الأحمر · SRC: ‏cybersecurity / red team / bug bounty / penetration-testing / vulnerability، ‏stars>200، ودُفعت خلال آخر 90 يوماً
  8. `skills` منظومة Skill: ‏claude-skills / agent-skills / claude-skill (رموز token بلا علامات اقتباس)، stars>50، ودُفعت خلال آخر 90 يوماً
  9. `creator` حزمة صنّاع المحتوى الكاملة: short-video / video-editing / ffmpeg / content creation / subtitles / livestream، ‏stars>200
  10. `src-hunt` ‏SRC · صيد الثغرات (جديد في v3): bug-bounty / 漏洞挖掘 / vulnerability-scanner / vulnerability-hunting، ‏stars>30، ودُفعت خلال آخر 90 يوماً
  11. `sec-learning` مواد تعلم أمن الشبكات (جديد في v3): pentest / ctf / web-security / cybersecurity-learning / security-roadmap، ‏stars>200، ودُفعت خلال آخر 90 يوماً
  - **درس في صياغة الاستعلام (مُختبَر عملياً)**: مجموعات OR داخل الأقواس في GitHub Search لا تقبل إلا رموز token بلا علامات اقتباس؛ وضع عبارة مقتبسة (مثل `"claude skills"`) داخل قوس OR يُرجع مباشرة `total_count=0` (ولهذا جاءت جولة قناة skills في v2 فارغة بالكامل). العبارات المقتبسة لا يمكن استخدامها إلا منفردة خارج الأقواس، مثل `"bug bounty" tools stars:>100` (54 نتيجة، تعمل طبيعياً). ويمكن استخدام كلمات مفتاحية صينية، مثل `漏洞挖掘 stars:>50` (47 نتيجة).
- **بذور المراقبة الأساسية WATCHLIST**: قائمة `SEEDS` المختارة يدوياً داخل الكود وتضم 23 عنصراً (منظومة Skill: ‏12 مستودعاً + موقع خارجي واحد هو Cocoloop، الكتابة 3، البحث العلمي 1، صنّاع المحتوى 8، أمن الشبكات 2)، وكل عنصر يحمل نقطة تعلم من سطر واحد مكتوبة يدوياً. تعرض اللوحة قسماً مستقلاً بعنوان «المراقبة الأساسية WATCHLIST» مجمّعاً حسب الفئة؛ فإذا أصاب فحصٌ مستودعاً يحمل اسم بذرة، دُمجت في بطاقته بياناته الحية ★/الشعبية/التقييم/زيادة هذه الجولة؛ أما البذور التي لم تُصَب فتُجلَب بالتناوب عبر «الانتعاش المنفرد» أثناء الفحص (انظر شرح v5 أدناه)، والتي لم يحن دورها بعد تُوسَم بـ«قيد المراقبة بالاسم».
- **مقارنة اللقطات**: تُحفَظ أعداد النجوم في لقطة كل جولة (KV ‏`intel:prev`)، وتُحسَب في الجولة التالية زيادة كل مستودع في هذه الجولة `starDelta`، وتظهر في اللوحة شارة `+N★ في هذه الجولة`، وتُرتَّب قائمة الصاعدة حسب الزيادة.
- **التحليل بالقواعد** (في الكود جدول كلمات مفتاحية `LEARNING_MAP` + صيغة موزونة، وتوسمه اللوحة بصدقٍ بـ«التحليل بالقواعد»)
  - درجة الشعبية 0-100: حجم النجوم 40 + زيادة هذه الجولة 30 + حداثة الدفع 20 + نشاط الـ fork ‏10
  - وسوم نقاط التعلم: 40 تطابقاً للكلمات المفتاحية (أضاف v2: ‏pentest/red-team←منهجية تقييم الفريق الأحمر، vulnerability←إدارة الثغرات، bug-bounty←أفكار الاختبار الجماعي SRC، ‏osint←استخبارات المصادر المفتوحة، skill←أنماط تغليف Skill، ‏subtitle←هندسة الترجمة المرئية، short-video←سير عمل الفيديو القصير، وغيرها)
  - التقييم: S عند ≥70، ‏A عند ≥45، ‏B لما عدا ذلك؛ وكل عنصر يحمل حكماً من قالب جاهز بسطر واحد، مثل: «+320★ في الجولة الأخيرة، مشروع لربط بروتوكول MCP بلغة Python، يستحق النظر في طريقة ربطه ببروتوكول MCP».
- **منظومة وسوم أمنية دقيقة** (جديدة في v3، في الكود `SECURITY_TAG_MAP`): تجري جولة إضافية من مطابقة كلمات الأمن المفتاحية على اسم المستودع + وصفه + topics، فتنتج وسوماً دقيقة مثل: حقن SQL / ‏XSS / ‏SSRF / ‏RCE / مسابقات CTF / استخبارات المصادر المفتوحة OSINT / تحليل البرمجيات الخبيثة / الأدلة الجنائية الرقمية / دفاع الفريق الأزرق / تدقيق الكود / اختراق الشبكات الداخلية / تصعيد الامتيازات / فحص الثغرات / أبحاث PoC / مراجعات الثغرات / مسارات التعلم / تدريبات الدفاع ضد التصيّد / الهندسة العكسية / اختبار الـ fuzzing / ‏DevSecOps، وتُدمَج مع وسوم نقاط التعلم مع إزالة التكرار، وبحدّ أقصى 6 وسوم لكل مستودع. تُطابَق الكلمات القصيرة RCE/PoC بحدود الكلمات (word boundary) تفادياً لوسم «source» خطأً بـ RCE و«epoch» خطأً بـ PoC؛ ولا يُوسَم «learning» بمسار التعلم إلا في سياق أمني، تفادياً لوسم مستودعات machine learning خطأً. جميع الوسوم تصنيفات موجَّهة للتعلم/البحث، وليست أدلة استغلال.
- **تفاعل اللوحة** (ترقية v2): شريط علوي لاصق يعرض ساعة حية بتوقيت بكين وحالة الفحص؛ أضافت مؤشرات KPI عدد القنوات وعدد البذور؛ يدعم شريط التصفية اللاصق التصفية ثنائية الأبعاد بالقناة + التقييم (S/A/B) والبحث؛ تحمل بطاقات القوائم الترتيب وشريط شعبية متحركاً وتوهّجاً عند التمرير؛ وكل بطاقة تؤدي مباشرة إلى صفحة المستودع في GitHub؛ وزر الفحص الفوري مخنوق بـ 30 دقيقة.
- **التصفية بالوسوم وسحابة الوسوم** (جديد في v3): وسم كل بطاقة شريحة (chip) قابلة للنقر، والنقر عليها يصفّي «كل الاستخبارات» بذلك الوسم (بالتركيب AND مع القناة/التقييم/البحث)، وبجوار شريط التصفية حبّة (pill) للوسم النشط يمكن مسحها بنقرة واحدة؛ وفوق منطقة الأمن سحابة «وسوم رائجة» تأخذ أعلى 15 وسماً حسب تكرار وسوم مستودعات قنوات الأمن الثلاث (security/src-hunt/sec-learning)، والنقر على وسم في السحابة يفعّل التصفية أيضاً.
- **ترقيم صفحات كل الاستخبارات** (جديد في v3): أصبحت شبكة «كل الاستخبارات» مرقّمة الصفحات من جهة العميل، 24 عنصراً في الصفحة (بما يتسق مع اتفاقية DEAL HUB)، مع أزرار السابق/التالي وأرقام الصفحات (تُطوى بعلامة حذف … عند كثرة الصفحات)، ويعرض سطر الحالة «الصفحة X / Y · المجموع N عنصراً (بعد التصفية)»؛ أي تغيير في التصفية/البحث/الوسم يعيد إلى الصفحة 1 ويعيد حساب عدد الصفحات على المجموعة المُصفّاة، وبعد قلب الصفحة يُمرَّر تلقائياً إلى أعلى منطقة «كل الاستخبارات». أما المناطق المتخصصة فتبقى عرض Top-N بلا ترقيم.

## تفاعل اللوحة (v4)

- **طيّ الأقسام**: أشرطة عناوين جميع الأقسام الرئيسية (قائمة الصاعدة، النجوم الجديدة الرائجة، منطقة AI/AGENT، مناطق القنوات، المراقبة الأساسية، كل الاستخبارات) قابلة للنقر: نقرة تطوي ونقرة توسّع (يشير ▼/▶ على يمين العنوان إلى الحالة، مع حركة تلاشٍ عند التوسيع). وفي شريط التصفية زرا «توسيع الكل / طيّ الكل» بنقرة واحدة. الافتراضي: الكل موسّع.
- **توسيع الكل داخل القسم**: يعرض كل قسم متخصص افتراضياً أول 6 بطاقات فقط، وعند تجاوزها يظهر في الأسفل زر «توسيع الكل: N عنصراً ▾»، نقرة تعرض الكل، ونقرة أخرى على «طيّ ▴» تعيد الوضع. وهذا مختلف عن طيّ القسم: الطيّ يطوي القسم بأكمله (كل المحتوى تحت العنوان)، أما «توسيع الكل» فيتحكم فقط في عدد البطاقات داخل القسم المتخصص.
- **مجموعتا تحكم في ترقيم الصفحات**: توجد أدوات ترقيم صفحات «كل الاستخبارات» **فوق الشبكة وأسفلها** (بنمط حدود خضراء لافت)، وتشترك أرقام الصفحات والسابق/التالي وسطر الحالة في حالة واحدة، فالنقر على أيٍّ منهما يزامن الأخرى؛ 24 عنصراً في الصفحة، وتتفاعل كالمعتاد مع تصفية القناة/التقييم/البحث/الوسم (تغيّر التصفية يعيد إلى الصفحة 1).
- **الموجز الرئاسي (نافذة عائمة)**: زر عائم دائم «📋 الموجز الرئاسي» في الزاوية السفلية اليمنى، يفتح نافذة موجز قابلة للسحب (اسحب من شريط العنوان، يدعم الفأرة واللمس، ولا يمكن سحبها خارج حدود الشاشة؛ في الزاوية العلوية اليمنى — للتصغير و✕ للإغلاق، وEsc يغلق أيضاً؛ تتكيف تلقائياً مع الشاشات الصغيرة بعرض 92vw). يُولَّد المحتوى من جهة الخادم بقوالب قواعد من البيانات الحالية: ملخص من سطر واحد + سطر شعبية الكلمات المفتاحية، ، ، (مع الوسوم الأمنية الرائجة)، ، (تظهر عند إعادة تسمية مستودع)، (عدد البذور المصابة والبذرة المتصدرة)، وكل عنصر قابل للنقر إلى GitHub. ويشير التذييل إلى وقت التوليد و«محرك قواعد (ليس من توليد ذكاء اصطناعي)». وتُضمَّن بيانات الموجز نفسها أيضاً بصيغة JSON داخل الصفحة (`#brief-data`)، ويمكن الحصول عليها منفصلة عبر `GET /api/brief`.

## الجديد في v5

- **تناوب انتعاش البذور**: في كل جولة فحص، وبالإضافة إلى عمليات البحث الـ 11، تُنفَق 3 استدعاءات إضافية كحدّ أقصى لواجهة Repos API الأساسية خصيصاً لانتعاش البذور «التي لم تُصَب في فحص هذه الجولة». يُخزَّن المؤشر في KV ‏`intel:seedcursor`، ويتناوب وفق ترتيب قائمة البذور (متخطياً المصابة منها)، فتُستكمَل كل البذور غير المصابة خلال بضع جولات. وتُحفَظ نتائج الانتعاش في `intel:seedlive`: الاسم الكامل الحالي/★/‏fork/وقت الدفع + طابع زمني للانتعاش؛ وحداثة بيانات بطاقة البذرة على ثلاث درجات: إصابة حية في فحص هذه الجولة ← انتعاش منفرد (تحمل البطاقة وسم «انتعاش منفرد» ووقته) ← تسمية ثابتة. يسير الانتعاش عبر `GET /repos/{owner}/{repo}`، فالمستودع المُعاد تسميته يُعاد توجيهه إلى العنوان الجديد، والاستجابة هي هويته الحالية: تعرض اللوحة الاسم الحالي مع وسم «الاسم الأصلي X أُعيدت تسميته»، وتكتب المعرّف الحالي عودةً إلى `intel:seedids`؛ أما البذور التي تُرجع 404 فتُوسَم بـ«يُشتبه في الحذف/إعادة تسمية غير مُتتبَّعة». حدّ استدعاءات GitHub في جولة واحدة = 11 بحثاً + 3 انتعاشات = 14 استدعاءً.
- **تاريخ اتجاهات المواضيع**: في كل جولة فحص تُجمَّع topics كل المستودعات (لكل موضوع: عدد المستودعات + مجموع النجوم، مع الاحتفاظ فقط بأعلى 40 موضوعاً بمجموع النجوم) وتُضاف إلى KV ‏`intel:topichist`، مع الاحتفاظ بأحدث 56 لقطة فقط (جولة كل 6 ساعات ≈ 14 يوماً). منهجية الاتجاه: مقارنة الزيادة في النجوم/عدد المستودعات مع اللقطة التاريخية الأقرب إلى ما قبل نحو 24 ساعة، وحساب «عدد جولات الاحترار المتتالية» (عدد الجولات، عودةً من أحدث لقطة، التي ازداد فيها مجموع النجوم ازدياداً صارماً متتالياً). تدخل أعلى 5 مواضيع ذات زيادة نجوم موجبة خلال 24 ساعة في بالموجز الرئاسي، وفي منطقة النظرة العامة باللوحة أيضاً سطر لاتجاهات المواضيع بالمنهجية نفسها أسفل سحابة الوسوم. وتُخفى تلقائياً عندما يقلّ التاريخ عن جولتين.
- **الدفع اليومي للموجز الرئاسي عبر Telegram**: بعد إعداد الأسرار (Secrets)، عندما ينجح فحص Cron ويكون توقيت بكين قد تجاوز 08:00، يُدفَع الموجز الرئاسي (بالبنية نفسها في نسخة الويب: نظرة اليوم/أعلى 3 صاعدة/أعلى 3 شعبية/تركيز الأمن/اتجاهات المواضيع/حركات إعادة التسمية + رابط اللوحة، بصيغة HTML، وفي حدود نحو 1800 حرف) إلى Telegram. ويمكن أن توجد أهداف دفع متعددة في آن واحد: `TG_CHAT_ID` (المحادثة الخاصة مع البوت)، `TG_CHANNEL_ID` (قناة محددة يدوياً، يمكن ملؤها بـ `@اسم_القناة` أو معرّف رقمي `-100…`، ومنذ v5.3 هي مجرد تجاوز اختياري)، بالإضافة إلى كل القنوات المسجلة تلقائياً في v5.3 (انظر البند التالي)، وتشترك كلها في `TG_BOT_TOKEN`؛ فإن لم يوجد أي هدف أُغلقت الميزة بصمت. **تنبيه: عند الدفع إلى قناة، يجب أن يكون البوت مشرفاً في تلك القناة، وإلا رفض Telegram النشر.** تُحكَم بوابة المرة الواحدة يومياً لكل هدف على حدة، وتُخزَّن الحالة في `intel:briefpush` (منذ v5.3 بالصيغة `{date, targets: {"dm"|"ch:<chatId>": {ok,ts}}}`؛ أما صيغة v5.2 وما قبلها `{date, dm, channel}` فتُهاجَر تلقائياً عند القراءة، وسجلات النجاح المُهاجَرة تستمر في حجب هدف ذلك اليوم كالمعتاد): يمكن إعادة محاولة هدف فاشل تلقائياً في فحوص لاحقة من اليوم نفسه، ولا يُعاد إرسال هدف ناجح في اليوم نفسه. التفعيل اليدوي: `POST /api/brief/push` (منذ v5.3.1 يتطلب مصادقة، انظر أدناه) يدفع إلى كل الأهداف دفعة واحدة (المحادثة الخاصة + القناة اليدوية + القنوات المسجلة تلقائياً)، ويُحسَب الخنق لكل هدف على حدة (أصبح KV ‏`intel:pushmanual` منذ v5.3.1 خريطة `{"dm"|"ch:<chatId>": ts}`، فلكل هدف دفع يدوي واحد كحدّ أقصى كل 6 ساعات؛ والقناة المسجلة حديثاً ليس لها سجل خنق، فيمكن إكمال دفعها فوراً دون انتظار انتهاء خنق أهداف أخرى؛ والطابع الزمني بالصيغة العالمية القديمة يُهاجَر تلقائياً عند القراءة إلى طابع خاص بـ `dm` فقط)؛ ويُبلِّغ حقل `brief.push` في `GET /api/brief` عن حالة الإعداد (`configured: {dm, manualChannel, autoChannels}`، يعطي أعداداً فقط، دون عناوين القنوات ومعرّفاتها الكاملة) ونتائج دفع اليوم لكل هدف.
- **التسجيل التلقائي للقنوات (v5.3)**: لا حاجة بعد الآن للبحث يدوياً عن معرّف القناة لملء `TG_CHANNEL_ID`. فبمجرد جعل بوت الموجز **مشرفاً** في أي قناة، يرسل Telegram تحديث `my_chat_member` إلى Webhook، فيسجّل Worker القناة بموجبه في KV ‏`intel:tgchannels` (بالصيغة `{ "<chatId>": {title, username, type, status, addedTs, updatedTs}}`)، وتصبح تلقائياً هدفاً للموجز اليومي والدفع اليدوي؛ وعندما يُخفَّض البوت إلى عضو عادي أو يُزال أو يُطرَد، تُوسَم تلك القناة بـ `removed` ويتوقف الدفع إليها. أما القنوات التي كان البوت مشرفاً فيها قبل v5.3 فلا يصلها هذا الحدث، فيُستكمَل تسجيلها عبر **أول منشور جديد** فيها (تحديث `channel_post`). ويمكن أن يتعايش `TG_CHANNEL_ID` كتجاوز يدوي مع التسجيل التلقائي، مع إزالة التكرار حسب chat id فلا تُرسَل إلا نسخة واحدة. وفي أمر `/stats` لا تظهر عناوين القنوات المسجلة تلقائياً **إلا لصاحب الجهاز** (عندما تكون محادثة الإصدار هي `TG_CHAT_ID` نفسه)، أما الآخرون فيرون العدد فقط.
- **إعادة محاولة القنوات الفاشلة**: عند خطأ بحث في أي قناة (مثل حدّ 403 لغير الموثّقين) تُعاد المحاولة تلقائياً مرة واحدة بعد ثانيتين قبل الحكم بالفشل، وتُسجَّل القنوات المُعادة محاولتها في بيانات الفحص الوصفية `meta.retriedChannels`؛ ويُسجَّل عدد بذور الانتعاش في `meta.seedRefreshed`.
- **مكدس الالتصاق العام**: دُمج شريط العنوان وسطر الوسوم الرائجة وشريط التصفية (القناة/التقييم/البحث/التوسيع والطيّ) في مكدس لاصق واحد (خلفية صلبة)، فيمكن التصفية مباشرة من أي موضع تمرير في الصفحة، ولم يعد متاحاً فقط داخل منطقة «كل الاستخبارات»؛ وتحتفظ منطقة «كل الاستخبارات» فقط بمجموعتي التحكم في ترقيم الصفحات العلوية والسفلية.

## أوامر البوت (v5.2)

يدعم بوت الموجز (وهو البوت نفسه المستخدم في الدفع اليومي) أوامر للقراءة فقط: أرسل أمراً إلى البوت في Telegram لتحصل على النتيجة، والبيانات من مصدر اللوحة نفسه (دفعة KV نفسها)، **وكلها للقراءة فقط، ولا تنفّذ أي إجراء إداري** (لا يمكنها تفعيل فحص، ولا تغيير إعدادات).

| الأمر | الوصف |
|---|---|
| `/brief` | الموجز الرئاسي لليوم (نص الدفع اليومي نفسه) |
| `/surge` | قائمة الصاعدة TOP5 (زيادة النجوم في هذه الجولة) |
| `/hot` | قائمة الشعبية TOP5 |
| `/sec` | تركيز الأمن (أعلى 5 من عائلة الأمن + الوسوم الأمنية الرائجة) |
| `/watchlist` | حالة المراقبة الأساسية (إجمالي البذور، تغطية الفحص/الانتعاش/الثابت، أعلى 5 بالنجوم، تنبيهات الاشتباه في الحذف وإعادة التسمية) |
| `/stats` | حالة الفحص (وقت آخر فحص، القنوات، الجديد في هذه الجولة، عدد بذور الانتعاش، إعداد الدفع وآخر تاريخ دفع) |
| `/panel` | روابط لوحة الاستخبارات وJSON الموجز |
| `/help` (أو `/start`) | قائمة الأوامر |

خطوات التفعيل (ثلاث خطوات إضافية فوق إعداد دفع v5):

1. أضف إلى Worker السرَّ `TG_WEBHOOK_SECRET`: ولّد بنفسك سلسلة عشوائية. فبدون هذا السر يُرجع `POST /tg/webhook` مباشرة 404، ويكون نظام الأوامر مغلقاً فعلياً؛ وبعد إضافته، تُرفَض بـ 403 كل الطلبات التي لا يتطابق ترويستها `x-telegram-bot-api-secret-token` معه.
2. سجّل Webhook (استبدل `<TOKEN>` و`<SECRET>` والنطاق بقيمك). **يجب أن تتضمن `allowed_updates` الأنواع الثلاثة `message` و`my_chat_member` و`channel_post`**: الأول للأوامر، والأخيران مصدر التسجيل التلقائي للقنوات في v5.3 (عندما يُجعَل البوت مشرف قناة، أو يظهر منشور جديد في قناة مسجلة)؛ فإذا حُذف الأخيران عملت الأوامر كالمعتاد، لكن القنوات لن تُسجَّل تلقائياً:
`curl "https://api.telegram.org/bot<TOKEN>/setWebhook" -d "url=https://<عنوانك>/tg/webhook" -d "secret_token=<SECRET>" -d "allowed_updates=[\"message\",\"my_chat_member\",\"channel_post\"]"`
3. سجّل قائمة الأوامر: خذ أولاً القائمة من `curl https://<عنوانك>/api/tg/commands`، ومرّر مصفوفة `commands` المُرجعة كمعامل `commands` إلى `setMyCommands`، فيرى المستخدمون قائمة الأوامر عند كتابة `/` في مربع الإدخال.

## مرساة المراقبة: معرّف المستودع الرقمي (v4)

قد تُعاد تسمية المستودعات أو يُنقَل مالكوها، فليس `full_name` مرساة مستقرة. منذ v4 تخزّن كل سجلاتنا معرّف مستودع GitHub الرقمي `id` (تُرجعه Search API كما هو)، وتُحاذى بناءً عليه:

- تغيّرت لقطة `intel:prev` إلى صيغة مفتاحها المعرّف `{ts, byId: { "<id>": {s: عدد النجوم, n: الاسم الكامل آنذاك}}}`. أما الصيغة المسطحة القديمة `{full_name: stars}` فتُهاجَر تلقائياً: في جولة الهجرة يُبنى جدول بحث بالاسم من اللقطة القديمة وتُحسَب الزيادات كالمعتاد، وفي نهاية الفحص تُكتب الصيغة الجديدة عودةً.
- عند المحاذاة بالمعرّف لحساب الزيادة، إذا تطابق المعرّف وتغيّر الاسم الكامل، يُحكَم بأنه **إعادة تسمية**: تُحفَظ الزيادة، ويحمل السجل `renamedFrom`، وتُسجَّل في بيانات الفحص الوصفية `meta.renames` واقعة `{from, to, stars}`، وتظهر في بالموجز الرئاسي.
- تخزّن بذور المراقبة الأساسية خريطة معرّفات منفصلة (KV ‏`intel:seedids`، بالصيغة `{الاسم الكامل للبذرة: id}`، تُحدَّث كل جولة فحص عند الإصابة بالاسم أو بمعرّف موجود): فبعد إعادة تسمية بذرة، تستمر الإصابة في الجولة التالية بالمعرّف، وتعرض اللوحة اسمها الكامل **الحالي** ورابطه.

## خطوات النشر

1. أنشئ في وحدة تحكم Cloudflare مساحة أسماء KV (مثل `github-intel-hub-data`).
2. أنشئ Worker جديداً، والصق نص `worker.js` كاملاً فيه (أو انشر هذا المجلد بـ wrangler).
3. اربط KV بـ Worker: يجب أن يكون اسم المتغير **`INTEL_KV`**، مشيراً إلى مساحة الأسماء في الخطوة 1.
4. (اختياري) أضف مشغّل Cron، يُنصَح بـ `17 */6 * * *` (فحص كل 6 ساعات؛ حدّ GitHub لغير الموثّقين منخفض، فلا تُكثر).
5. (اختياري) أضف السرَّ `GITHUB_TOKEN`: ملء رمز وصول شخصي من GitHub (تكفي قراءة البيانات العامة) يرفع حدّ الواجهة كثيراً؛ وبدونه يعمل أيضاً.
6. (اختياري) الدفع عبر Telegram للموجز الرئاسي: أضف السرَّ `TG_BOT_TOKEN` (الرمز الذي يعطيه BotFather)، ثم أضف `TG_CHAT_ID` (معرّف محادثتك الخاصة)؛ وإذا أردت استخدام واجهة الدفع اليدوي `POST /api/brief/push`، أضف أيضاً السرَّ `PUSH_KEY` (ولّد بنفسك سلسلة عشوائية، وضعها عند الاستدعاء في ترويسة الطلب `x-push-key`؛ وبدون هذا السر تُرجع الواجهة مباشرة 403 وتُغلَق)؛ ولا حاجة لإعداد معرّفات أهداف القنوات يدوياً — فبعد تفعيل Webhook وفق قسم «أوامر البوت (v5.2)» (متضمناً `my_chat_member`/`channel_post`)، اجعل البوت مشرفاً في القناة فيُسجَّل تلقائياً (v5.3)، و`TG_CHANNEL_ID` (‏`@اسم_مستخدم` القناة أو معرّفها الرقمي `-100…`) مجرد تجاوز يدوي اختياري. وعند الدفع إلى قناة يجب أن يكون البوت مشرفاً فيها. فإن لم تُضَف أيٌّ منها فلن يُدفَع شيء. وإذا أردت أيضاً تفعيل أوامر البوت، أضف السرَّ `TG_WEBHOOK_SECRET` وسجّل Webhook وقائمة الأوامر وفق قسم «أوامر البوت (v5.2)».
7. افتح عنوان Worker وانقر «الفحص الفوري» لجلب أول دفعة بيانات؛ أو `curl -X POST https://<عنوانك>/api/refresh`.

## الواجهات

| المسار | الوصف |
|---|---|
| `GET /` | لوحة الاستخبارات (HTML) |
| `GET /api/repos` | JSON أحدث دفعة مستودعات (يتضمن heat/grade/learnTags/verdict/starDelta)، مع بيانات دمج بذور `watchlist` |
| `GET /api/watchlist` | JSON قائمة بذور المراقبة الأساسية (يتضمن فئة كل بذرة ونقطة تعلمها اليدوية وبيانات إصابتها الحية `live`، و`null` عند عدم الإصابة) |
| `GET /api/stats` | بيانات آخر جولة فحص الوصفية (الوقت، عدد عناصر كل قناة، الأخطاء، وقائع إعادة التسمية `renames`) |
| `GET /api/brief` | JSON الموجز الرئاسي (بيانات نافذة اللوحة العائمة نفسها: النظرة، أعلى 3 صاعدة/شعبية، تركيز الأمن/Skill، حركات إعادة التسمية، شعبية الكلمات المفتاحية، اتجاهات المواضيع، حركات المراقبة الأساسية)، مع حالة دفع `brief.push` (أعداد `configured: {dm, manualChannel, autoChannels}` ونتائج اليوم لكل هدف، دون عناوين القنوات/معرّفاتها الكاملة) |
| `POST /api/brief/push` | دفع الموجز الرئاسي يدوياً إلى أهداف TG (المحادثة الخاصة + القناة اليدوية + القنوات المسجلة تلقائياً). يتطلب السرَّ `PUSH_KEY`: عند عدم إعداده يُرجع 403 ‏`status: "push_disabled"`، وعند غياب/خطأ ترويسة `x-push-key` يُرجع 401 ‏`status: "unauthorized"` (بلا دفع، وبلا كتابة خنق)؛ وبعد نجاح المصادقة يُخنَق كل هدف على حدة 6 ساعات، فلا يُدفَع إلا للأهداف غير المخنوقة، وتتضمن الاستجابة `targets` (مفاتيح الأهداف المدفوعة هذه المرة) و`skipped` (مفاتيح الأهداف المتخطاة بسبب الخنق)، وعند غياب أي هدف يُرجع `status: "not_configured"` |
| `GET /api/tg/commands` | JSON قائمة أوامر البوت (لاستخدام `setMyCommands`، ‏8 أوامر) |
| `POST /tg/webhook` | مدخل Telegram Webhook (أوامر البوت للقراءة فقط + التسجيل التلقائي للقنوات؛ يتطلب السرَّ `TG_WEBHOOK_SECRET`، عند عدم إعداده يُرجع 404، وعند خطأ المفتاح 403) |
| `POST /api/refresh` | تفعيل فحص يدوياً، الاستدعاءات المتكررة خلال 30 دقيقة تُخنَق (تُرجع `throttled: true`) |
| ‏Cron ‏`scheduled()` | فحص مجدول، لا يخضع للخنق اليدوي |

مفاتيح KV: ‏`intel:latest` (أحدث البيانات)، `intel:prev` (لقطة نجوم الجولة السابقة، منذ v4 بصيغة مفاتيح المعرّف)، `intel:meta` (بيانات الفحص الوصفية)، `intel:seedids` (خريطة معرّفات مستودعات البذور)، `intel:seedcursor` (مؤشر تناوب انتعاش البذور)، `intel:seedlive` (نتائج انتعاش البذور)، `intel:topichist` (لقطات تاريخ اتجاهات المواضيع، أحدث 56)، `intel:briefpush` (حالة الدفع اليومي للموجز، منذ v5.3 بالصيغة `{date, targets}` مسجلة بمفاتيح الأهداف)، `intel:pushmanual` (خنق الدفع اليدوي، منذ v5.3.1 خريطة حسب الهدف `{"dm"|"ch:<chatId>": ts}`، والصيغة العالمية القديمة تُهاجَر عند القراءة)، `intel:tgchannels` (جدول القنوات المسجلة تلقائياً، أُضيف في v5.3).

## ملاحظات حول صدق البيانات

- مصدر البيانات الوحيد هو نتائج البحث العامة من GitHub Search API، والترتيب ومعايير الإدراج يقررها GitHub؛ استعلامات القنوات قواعد كلمات مفتاحية، وليست Trending الرسمي من GitHub.
- **زيادة النجوم تحتاج إلى جولتي فحص على الأقل**: في الجولة الأولى تكون زيادة كل المستودعات فارغة، ويكتب التحليل «جديد في قاعدة الاستخبارات»؛ ومن الجولة الثانية تبدأ `+N★` بالظهور.
- حدّ الاستدعاءات غير الموثّقة منخفض جداً (Search API نحو 10 مرات/دقيقة، مع حصة كل ساعة)، فـ 11 استدعاءً في الجولة لا مشكلة فيها، لكن لا تُحدّث يدوياً بتكرار عالٍ — الكود يفرض أصلاً خنقاً بـ 30 دقيقة.
- عند فشل جلب قناة ما، تُوسَم تلك القناة في شريط اللوحة المتحرك بأنها غير طبيعية، وتُستخدَم بياناتها القديمة من الجولة السابقة، دون مسح البيانات كلها؛ وعندما تفشل كل القنوات لا تُستبدَل البيانات الموجودة.
- التحليلات والتقييمات ونقاط التعلم كلها مخرجات قواعد، وقد تخطئ الحكم (مثل مستودعات تحشو الكلمات المفتاحية في الوصف)، وهي لمرجعية التصفية فقط، ولا تشكّل ضماناً لاستنتاج «يستحق التعلم».
- ‏KV تخزين متّسق في النهاية (eventually consistent)، فقد تقرأ اللوحة بيانات قديمة لفترة وجيزة خلال عشرات الثواني بعد كتابة الفحص للتوّ، وهذا أمر طبيعي.
