Cloudflare Workers에서 실행되는 '해커 정보 센터' 스타일 패널입니다. GitHub 인기 리포지토리를 정기적으로 순찰하고, **규칙 엔진**(AI가 아님)으로 인기도를 판정하고 학습 포인트를 표시하여, 최근 어떤 오픈소스 프로젝트가 급상승하고 있으며 각각 무엇을 배울 가치가 있는지 알려줍니다. 매일 아침 '대통령 브리핑'은 Telegram 개인 채팅과 채널로 자동 전송됩니다(채널에서 Bot을 관리자로 지정하면 자동으로 인식되며, 별도 설정이 필요 없습니다).

단일 파일 `worker.js`, 의존성 없음, 데이터는 KV에 저장됩니다. 다크 패널: 거의 검은 배경 + 네온 그린/시안 + 고정폭 글꼴 + 스캔라인 질감 + 티커.

## 기능

- **11개 정보 채널**(v2에서 3개 추가, v3에서 2개 더 추가; 순찰 1회당 GitHub Search API 호출 11회로, 무료 플랜의 서브요청 한도 50회를 크게 밑돕니다)
1. `surge` 급상승 신성: 최근 30일 이내 생성, stars>50
2. `trending-week` 이번 주 인기: 최근 7일 이내 푸시 있음, stars>5000인 노련한 인기 리포지토리
3. `ai-agent` AI/AGENT: ai-agent / llm / mcp 키워드
4. `workers` 엣지/Bot: cloudflare-workers / serverless / telegram-bot
5. `media` 멀티미디어 생성: comfyui / image-generation / text-to-speech
6. `devtools` 개발 도구: developer-tools / browser-automation / playwright
7. `security` 사이버 보안·레드팀·SRC: cybersecurity / red team / bug bounty / penetration-testing / vulnerability, stars>200, 최근 90일 이내 푸시 있음
8. `skills` Skill 생태계: claude-skills / agent-skills / claude-skill(따옴표 없는 token), stars>50, 최근 90일 이내 푸시 있음
9. `creator` 셀프미디어 풀세트: short-video / video-editing / ffmpeg / content creation / subtitles / livestream, stars>200
10. `src-hunt` SRC·취약점 발굴(v3 신규): bug-bounty / 漏洞挖掘 / vulnerability-scanner / vulnerability-hunting, stars>30, 최근 90일 이내 푸시 있음
11. `sec-learning` 사이버 보안 학습 자료(v3 신규): pentest / ctf / web-security / cybersecurity-learning / security-roadmap, stars>200, 최근 90일 이내 푸시 있음
- **쿼리 문법 교훈(실측)**: GitHub Search의 OR 괄호 그룹에는 따옴표 없는 token만 넣을 수 있습니다. 따옴표가 있는 구(예: `"claude skills"`)를 OR 괄호에 넣으면 곧바로 `total_count=0`이 반환됩니다(v2의 skills 채널이 이 때문에 한 라운드 전체가 비었습니다). 따옴표가 있는 구는 괄호 밖에서 단독으로만 사용할 수 있습니다. 예: `"bug bounty" tools stars:>100`(54개, 정상). 중국어 키워드도 사용할 수 있습니다. 예: `漏洞挖掘 stars:>50`(47개).
- **중점 모니터링 시드 WATCHLIST**: 코드 안의 `SEEDS`에 있는 수작업으로 엄선한 목록 총 23개(Skill 생태계 리포지토리 12개 + 외부 사이트 Cocoloop 1개, 글쓰기 3개, 과학 연구 1개, 셀프미디어 8개, 사이버 보안 2개)로, 각 항목마다 사람이 직접 쓴 학습 포인트 한 문장이 붙어 있습니다. 패널에는 독립된 '중점 모니터링 WATCHLIST' 섹션이 있어 카테고리별로 그룹화하여 보여줍니다. 순찰에서 같은 이름의 리포지토리에 적중한 시드는 카드에 실시간 ★/인기도/등급/이번 라운드 증가분이 병합되어 표시되고, 적중하지 않은 시드는 순찰이 '개별 신선도 유지'로 차례대로 가져옵니다(아래 v5 설명 참조). 아직 차례가 오지 않은 것은 '지명 모니터링 중'으로 표시됩니다.
- **스냅샷 비교**: 라운드마다 스타 수를 스냅샷(KV `intel:prev`)에 저장하고, 다음 라운드에서 각 리포지토리의 이번 라운드 증가분 `starDelta`를 계산합니다. 패널에는 `+N★ 이번 라운드` 배지가 있고, 급상승 순위는 증가분으로 정렬됩니다.
- **규칙 기반 판정**(코드에서는 `LEARNING_MAP` 키워드 표 + 가중 공식이며, 패널에는 '규칙 기반 판정'이라고 사실대로 표시합니다)
- 인기도 점수 0-100: 스타 규모 40 + 이번 라운드 증가분 30 + 푸시 신선도 20 + fork 활성도 10
- 학습 포인트 태그: 키워드 매핑 40개(v2에서 추가된 pentest/red-team→레드팀 평가 방법, vulnerability→취약점 관리, bug-bounty→SRC 크라우드 테스트 접근법, osint→오픈소스 인텔리전스, skill→Skill 캡슐화 패턴, subtitle→자막 엔지니어링, short-video→숏폼 동영상 워크플로 등)
- 등급: S ≥70, A ≥45, B는 그 외. 각 항목마다 템플릿 판정 한 문장이 붙습니다. 예: '최근 라운드에서 +320★, Python MCP 프로토콜 연동 프로젝트로, 그 MCP 프로토콜 연동을 볼 가치가 있습니다.'
- **보안 세분화 태그 체계**(v3 신규, 코드에서는 `SECURITY_TAG_MAP`): 리포지토리 이름+설명+topics에 대해 보안 키워드 매칭을 한 번 더 수행하여 SQL 인젝션 / XSS / SSRF / RCE / CTF 대회 / 오픈소스 인텔리전스 OSINT / 악성코드 분석 / 디지털 포렌식 / 블루팀 방어 / 코드 감사 / 내부 네트워크 침투 / 권한 상승 / 취약점 스캔 / PoC 연구 / 취약점 회고 / 학습 로드맵 / 피싱 방어 훈련 / 리버스 엔지니어링 / 퍼징 / DevSecOps 등의 세분화 태그를 생성하고, 학습 포인트 태그와 병합·중복 제거하여 리포지토리당 최대 6개로 제한합니다. 짧은 단어 RCE/PoC는 단어 경계 매칭을 사용해 'source'를 RCE로, 'epoch'를 PoC로 잘못 표시하지 않습니다. 'learning'은 보안 맥락에서만 학습 로드맵으로 태그를 붙여 machine learning 리포지토리가 잘못 표시되는 것을 방지합니다. 태그는 모두 학습/연구용 분류이며, 악용 가이드가 아닙니다.
- **패널 상호작용**(v2 업그레이드): 스티키 상단 바에 베이징 시간 실시간 시계와 순찰 상태가 있습니다. KPI에 채널 수와 시드 수가 추가되었습니다. 스티키 필터 바는 채널 + 등급(S/A/B) 2차원 필터와 검색을 지원합니다. 각 순위 카드에는 순위, 인기도 바 애니메이션, 호버 글로우가 있고, 각 카드에서 GitHub 리포지토리 페이지로 바로 이동합니다. 즉시 순찰 버튼에는 30분 스로틀링이 있습니다.
- **태그 필터와 태그 클라우드**(v3 신규): 각 카드의 태그는 클릭 가능한 chip으로, 클릭하면 해당 태그로 '전체 정보'를 필터링합니다(채널/등급/검색과 AND로 조합). 필터 바 옆에는 활성 태그 pill이 있어 한 번의 클릭으로 지울 수 있습니다. 사이버 보안 전용 구역 위에는 '인기 태그' 클라우드가 있어, 보안 3개 채널(security/src-hunt/sec-learning) 리포지토리의 태그 빈도에서 상위 15개를 가져오며, 클라우드의 태그를 클릭해도 마찬가지로 필터가 실행됩니다.
- **전체 정보 페이지네이션**(v3 신규): '전체 정보' 그리드는 클라이언트 측 페이지네이션으로 바뀌어 페이지당 24개(DEAL HUB 규약과 동일), 이전/다음 및 페이지 번호 버튼(페이지가 많으면 줄임표로 접음)이 있고, 상태 행에는 'X / Y 페이지 · 총 N개(필터 후)'가 표시됩니다. 필터/검색/태그가 바뀔 때마다 1페이지로 돌아가고 필터 후 집합으로 페이지 수를 다시 계산합니다. 페이지를 넘기면 자동으로 '전체 정보' 구역 상단으로 스크롤됩니다. 각 전용 구역은 여전히 Top-N 표시이며 페이지네이션을 하지 않습니다.

## 패널 상호작용(v4)

- **섹션 접기**: 모든 주요 섹션(급상승 순위, 인기 신성, AI/AGENT 전용 구역, 각 채널 전용 구역, 중점 모니터링, 전체 정보)의 제목 바를 클릭할 수 있어, 한 번 클릭하면 접히고 다시 클릭하면 펼쳐집니다(제목 오른쪽의 ▼/▶가 상태를 나타내며, 펼칠 때 페이드인 전환 애니메이션이 있습니다). 필터 바에는 '모두 펼치기 / 모두 접기' 원클릭 버튼이 있습니다. 기본값은 모두 펼침입니다.
- **섹션 내 모두 펼치기**: 각 전용 구역은 기본적으로 처음 6장의 카드만 보여주고, 그보다 많으면 하단에 '모두 N개 펼치기 ▾' 버튼이 있어 클릭하면 전부를 볼 수 있고, 다시 '접기 ▴'를 클릭하면 복원됩니다. 섹션 접기와는 다른 것입니다: 접기는 섹션 전체(제목 아래의 모든 콘텐츠)를 접고, 모두 펼치기는 전용 구역 안의 카드 수만 제어합니다.
- **이중 페이지네이션 컨트롤**: '전체 정보'의 페이지네이션 컨트롤은 그리드 **위와 아래에 한 세트씩** 있으며(눈에 띄는 초록 테두리 스타일), 페이지 번호, 이전/다음, 상태 행이 동일한 상태를 공유해 어느 쪽을 눌러도 다른 쪽과 동기화됩니다. 페이지당 24개이며, 채널/등급/검색/태그 필터와 평소처럼 연동됩니다(필터가 바뀌면 1페이지로 돌아갑니다).
- **대통령 브리핑(플로팅 창)**: 오른쪽 아래에 상주하는 '📋 대통령 브리핑' 플로팅 버튼을 누르면 드래그 가능한 브리핑 창이 열립니다(제목 바를 누른 채 드래그, 마우스와 터치 지원, 화면 경계 밖으로 나가지 않음. 오른쪽 위의 —는 최소화, ✕는 닫기, Esc로도 닫을 수 있음. 작은 화면에서는 자동으로 92vw 너비에 맞춥니다). 콘텐츠는 서버가 현재 데이터로 규칙 템플릿을 이용해 생성합니다: 한 문장 요약 + 키워드 인기도 한 줄,,, (인기 보안 태그 포함),, (리포지토리 이름 변경이 있을 때 표시), (시드 적중 수와 선두 시드)으로, 각 항목에서 GitHub로 이동할 수 있습니다. 하단에는 생성 시간과 '규칙 엔진(AI 생성이 아님)'이 표시됩니다. 동일한 브리핑 데이터는 JSON 형식으로 페이지에도 내장되어 있으며(`#brief-data`), `GET /api/brief`로 별도로 가져올 수도 있습니다.

## v5 신규 사항

- **시드 신선도 유지 로테이션**: 각 순찰 라운드에서는 11회 검색 외에도 최대 3회까지 핵심 Repos API 호출을 추가로 사용해 '이번 라운드 순찰에서 적중하지 않은' 시드 전용으로 신선도를 유지합니다. 커서는 KV `intel:seedcursor`에 저장하고 시드 목록 순서대로 로테이션합니다(이미 적중한 것은 건너뜀). 몇 라운드면 적중하지 않은 시드 전부를 한 바퀴 돌 수 있습니다. 신선도 유지 결과는 `intel:seedlive`에 저장합니다: 현재 전체 이름/★/fork/푸시 시간 + 신선도 유지 타임스탬프. 시드 카드의 데이터 신선도는 3단계입니다——이번 라운드 순찰에서 실시간 적중 → 개별 신선도 유지(카드에 '개별 신선도 유지' 표시와 시간이 붙음) → 정적 지명. 신선도 유지는 `GET /repos/{owner}/{repo}`를 사용하며, 이름이 변경된 리포지토리는 새 주소로 리다이렉트되고 응답이 곧 현재 신원이 됩니다: 패널에는 현재 이름이 표시되고 '원래 X에서 이름 변경'이라고 표시되며, 동시에 현재 id가 `intel:seedids`에 다시 기록됩니다. 404가 반환되는 시드는 '삭제 의심/이름 변경 미추적'으로 표시됩니다. 순찰 1회의 GitHub 호출 상한 = 검색 11회 + 신선도 유지 3회 = 14회입니다.
- **토픽 트렌드 기록**: 각 순찰 라운드마다 전체 리포지토리의 topics를 집계하고(토픽별: 리포지토리 수 + 누적 스타, 누적 스타 상위 40개만 유지) KV `intel:topichist`에 추가합니다. 최근 56개 스냅샷만 유지합니다(6시간에 1라운드 ≈ 14일). 트렌드 기준: 약 24시간 전에 가장 가까운 과거 스냅샷과 스타 수/리포지토리 수 증가분을 비교하고, '연속 상승 라운드 수'(최신 스냅샷부터 거슬러 올라가며 누적 스타가 연속으로 엄격히 증가한 라운드 수)를 계산합니다. 24h 스타 증가분이 양수인 상위 5개 토픽이 대통령 브리핑의 에 들어가고, 패널 개요 구역의 태그 클라우드 아래에도 동일한 기준의 토픽 트렌드가 한 줄 표시됩니다. 기록이 2라운드 미만이면 자동으로 숨겨집니다.
- **대통령 브리핑 Telegram 매일 전송**: Secret을 설정하면, Cron 순찰이 성공하고 베이징 시간이 08:00을 지난 뒤에 대통령 브리핑(Web 버전과 동일한 구조: 오늘의 정세/급상승 TOP3/인기 TOP3/사이버 보안 포커스/토픽 트렌드/이름 변경 동향 + 패널 링크, HTML 형식, 약 1800자 이내)을 Telegram으로 전송합니다. 전송 대상은 여러 개가 동시에 존재할 수 있습니다: `TG_CHAT_ID`(Bot 개인 채팅), `TG_CHANNEL_ID`(수동으로 지정한 채널, `@채널명` 또는 `-100…` 숫자 id를 입력할 수 있으며, v5.3부터는 선택적 재정의일 뿐입니다), 여기에 v5.3에서 자동 등록된 모든 채널(다음 항목 참조)이 더해지며, `TG_BOT_TOKEN`을 공유합니다. 전송 대상이 하나도 없으면 기능은 조용히 꺼집니다. **주의: 채널로 전송할 때 Bot은 해당 채널의 관리자여야 하며, 그렇지 않으면 Telegram이 게시를 거부합니다.** 하루 1회 게이트는 대상별로 각각 판정하고 상태는 `intel:briefpush`에 저장합니다(v5.3부터는 `{date, targets: {"dm"|"ch:<chatId>": {ok,ts}}}`이며, v5.2 이전의 `{date, dm, channel}` 구 형식은 읽을 때 자동으로 마이그레이션되고, 마이그레이션된 성공 기록은 그대로 당일 해당 대상의 게이트 역할을 합니다): 어떤 대상이 실패하면 당일 후속 순찰에서 자동으로 재시도할 수 있고, 이미 성공한 대상은 당일 다시 보내지 않습니다. 수동 트리거: `POST /api/brief/push`(v5.3.1부터 인증 필요, 아래 참조)로 모든 대상(개인 채팅 + 수동 채널 + 자동 등록 채널)에 한 번에 전송합니다. 스로틀링은 대상별로 각각 계산합니다(KV `intel:pushmanual`은 v5.3.1부터 `{"dm"|"ch:<chatId>": ts}` 매핑이며, 각 대상은 6시간에 최대 1회까지 수동 전송할 수 있습니다. 새로 등록된 채널에는 스로틀링 기록이 없어 다른 대상의 스로틀링 만료를 기다리지 않고 즉시 보충 전송할 수 있습니다. 구 전역 형식의 타임스탬프는 읽을 때 `dm`만의 스탬프로 자동 마이그레이션됩니다). `GET /api/brief`의 `brief.push` 필드는 설정 상태(`configured: {dm, manualChannel, autoChannels}`, 채널 제목과 전체 id는 포함하지 않고 개수만 제공)와 오늘 각 대상의 전송 결과를 반환합니다.
- **채널 자동 등록(v5.3)**: 더 이상 채널 id를 수동으로 조회해 `TG_CHANNEL_ID`에 입력할 필요가 없습니다. 브리핑 Bot을 임의 채널의 **관리자**로 지정하면 Telegram이 Webhook으로 `my_chat_member` 업데이트를 보내고, Worker는 이를 근거로 채널을 KV `intel:tgchannels`(`{ "<chatId>": {title, username, type, status, addedTs, updatedTs}}`)에 등록하여 자동으로 매일 브리핑과 수동 전송의 대상이 됩니다. Bot이 일반 멤버로 강등되거나, 제거되거나, 추방되면 해당 채널은 `removed`로 표시되고 전송이 중단됩니다. v5.3 이전에 이미 관리자였던 채널에는 이 이벤트가 없으므로, 해당 채널의 **첫 번째 새 게시물**(`channel_post` 업데이트)로 보충 등록됩니다. `TG_CHANNEL_ID`는 수동 재정의로서 자동 등록과 공존할 수 있으며, chat id로 중복을 제거해 한 통만 보냅니다. `/stats` 명령에서 자동 등록 채널의 **제목은 소유자에게만 보입니다**(명령을 보낸 chat이 `TG_CHAT_ID` 본인일 때). 다른 사람에게는 개수만 보입니다.
- **채널 실패 시 재시도**: 어느 채널의 검색에서 오류(예: 미인증 한도 403)가 발생하면 2초 간격을 두고 자동으로 한 번 재시도한 뒤 실패로 판정합니다. 재시도한 채널은 순찰 메타 정보 `meta.retriedChannels`에 기록됩니다. 시드 신선도 유지 수는 `meta.seedRefreshed`에 기록됩니다.
- **전역 스티키 스택**: 제목 바, 인기 태그 행, 필터 바(채널/등급/검색/펼치기·접기)가 하나의 스티키 스택(불투명 배경)으로 합쳐져, 페이지의 어느 스크롤 위치에서든 직접 필터링할 수 있게 되었습니다. 더 이상 '전체 정보' 구역 안에서만 쓸 수 있는 것이 아닙니다. '전체 정보' 구역 안에는 위아래 두 세트의 페이지네이션 컨트롤만 남습니다.

## Bot 명령어(v5.2)

브리핑 Bot(매일 전송과 동일한 Bot)은 읽기 전용 명령을 지원합니다: Telegram에서 Bot에게 명령을 보내기만 하면 됩니다. 데이터는 패널과 동일한 출처(동일한 KV 묶음)이며, **모두 읽기 전용으로 어떤 관리 동작도 하지 않습니다**(순찰을 트리거할 수 없고, 설정도 변경할 수 없습니다).

| 명령어 | 설명 |
|---|---|
| `/brief` | 오늘의 대통령 브리핑(매일 전송과 동일한 텍스트) |
| `/surge` | 급상승 순위 TOP5(이번 라운드 스타 증가분) |
| `/hot` | 인기도 순위 TOP5 |
| `/sec` | 사이버 보안 포커스(보안 패밀리 TOP5 + 인기 보안 태그) |
| `/watchlist` | 중점 모니터링 상태(시드 총수, 순찰/신선도 유지/정적 커버, 스타 TOP5, 삭제 의심 및 이름 변경 힌트) |
| `/stats` | 순찰 상태(마지막 순찰 시간, 채널, 이번 라운드 신규, 시드 신선도 유지 수, 전송 설정 및 최근 전송 날짜) |
| `/panel` | 정보 패널과 브리핑 JSON 링크 |
| `/help`(또는 `/start`) | 명령어 목록 |

개통 단계(v5 전송 설정을 기반으로 3단계 추가):

1. Worker에 Secret `TG_WEBHOOK_SECRET`을 추가합니다: 임의의 무작위 문자열을 직접 생성하세요. 이 Secret이 없으면 `POST /tg/webhook`은 곧바로 404를 반환하고 명령 시스템은 꺼진 것과 같습니다. 추가한 뒤에는 요청 헤더 `x-telegram-bot-api-secret-token`이 그것과 일치하지 않는 요청은 모두 403이 됩니다.
2. Webhook을 등록합니다(`<TOKEN>`, `<SECRET>` 및 도메인을 자신의 것으로 교체하세요). **`allowed_updates`에는 반드시 `message`, `my_chat_member`, `channel_post` 세 종류가 포함되어야 합니다**: 첫 번째는 명령용이고, 뒤의 두 가지는 v5.3 채널 자동 등록의 출처입니다(Bot이 채널 관리자로 지정될 때, 또는 이미 등록된 채널에 새 게시물이 생길 때 채널을 등록합니다). 뒤의 두 가지를 빠뜨리면 명령은 정상적으로 동작하지만 채널은 자동 등록되지 않습니다:
`curl "https://api.telegram.org/bot<TOKEN>/setWebhook" -d "url=https://<내 주소>/tg/webhook" -d "secret_token=<SECRET>" -d "allowed_updates=[\"message\",\"my_chat_member\",\"channel_post\"]"`
3. 명령 메뉴를 등록합니다: 먼저 목록을 가져옵니다 `curl https://<내 주소>/api/tg/commands`. 반환된 `commands` 배열을 `commands` 매개변수로 하여 `setMyCommands`를 호출하면, 사용자가 입력창에 `/`를 입력할 때 명령 메뉴를 볼 수 있습니다.

## 모니터링 앵커: 리포지토리 id(v4)

리포지토리는 이름이 변경되거나 소유자가 이전될 수 있어 `full_name`은 안정적인 앵커가 아닙니다. v4부터 각 레코드는 GitHub 숫자 리포지토리 `id`(Search API가 그대로 반환)를 저장하고, 이를 기준으로 맞춥니다:

- 스냅샷 `intel:prev`는 id 키 형식 `{ts, byId: { "<id>": {s: 스타 수, n: 당시 전체 이름}}}`으로 변경되었습니다. 구 평면 `{full_name: stars}` 형식은 자동 마이그레이션됩니다: 마이그레이션 라운드에서는 먼저 구 스냅샷으로 이름 조회 표를 만들어 평소처럼 증가분을 계산하고, 순찰이 끝나면 새 형식으로 다시 기록합니다.
- id로 맞춰 증가분을 계산할 때 id는 같지만 전체 이름이 바뀌었으면 **이름 변경**으로 판정합니다: 증가분은 유지되고, 레코드에 `renamedFrom`이 붙으며, 순찰 메타 정보 `meta.renames`에 `{from, to, stars}` 한 건이 기록되고, 대통령 브리핑의 에 나타납니다.
- 중점 모니터링 시드는 별도로 id 매핑을 저장합니다(KV `intel:seedids`, `{시드 전체 이름: id}`, 매 순찰 라운드에서 이름 또는 기존 id로 적중할 때 업데이트): 시드 이름이 변경된 뒤에도 다음 라운드에서 id로 적중하며, 패널에는 그 **현재** 전체 이름과 링크가 표시됩니다.

## 배포 단계

1. Cloudflare 콘솔에서 KV namespace를 만듭니다(예: `github-intel-hub-data`).
2. Worker를 새로 만들고 `worker.js` 전체를 붙여넣습니다(또는 wrangler로 이 디렉터리를 배포합니다).
3. Worker에 KV를 바인딩합니다: 변수 이름은 반드시 **`INTEL_KV`**여야 하며, 1단계의 namespace를 가리켜야 합니다.
4. (선택) Cron 트리거를 추가합니다. 권장값은 `17 */6 * * *`입니다(6시간마다 1회 순찰. 미인증 GitHub 한도가 낮으므로 너무 자주 실행하지 마세요).
5. (선택) Secret `GITHUB_TOKEN`을 추가합니다: GitHub Personal Access Token(공개 데이터 읽기 전용이면 충분)을 입력하면 API 한도를 크게 높일 수 있습니다. 입력하지 않아도 동작합니다.
6. (선택) 대통령 브리핑 Telegram 전송: Secret `TG_BOT_TOKEN`(BotFather가 준 token)을 추가하고, 이어서 `TG_CHAT_ID`(내 개인 채팅 id)를 추가합니다. 수동 전송 인터페이스 `POST /api/brief/push`를 사용하려면 Secret `PUSH_KEY`를 추가로 넣습니다(임의의 무작위 문자열을 직접 생성하고, 호출할 때 요청 헤더 `x-push-key`에 넣습니다. 이 Secret이 없으면 해당 인터페이스는 곧바로 403으로 닫힙니다). 채널 대상은 id를 수동으로 설정할 필요가 없습니다——'Bot 명령어(v5.2)' 섹션에 따라 Webhook(`my_chat_member`/`channel_post` 포함)을 개통한 뒤 Bot을 채널 관리자로 지정하면 자동 등록됩니다(v5.3). `TG_CHANNEL_ID`(채널 `@사용자명` 또는 `-100…` 숫자 id)는 선택적 수동 재정의로만 사용합니다. 채널로 전송할 때 Bot은 해당 채널의 관리자여야 합니다. 둘 다 추가하지 않으면 전송하지 않습니다. Bot 명령까지 개통하려면 Secret `TG_WEBHOOK_SECRET`을 추가로 넣고 'Bot 명령어(v5.2)' 섹션에 따라 Webhook과 명령 메뉴를 등록합니다.
7. Worker 주소를 열고 '즉시 순찰'을 클릭해 첫 번째 데이터를 가져옵니다. 또는 `curl -X POST https://<내 주소>/api/refresh`를 실행합니다.

## 인터페이스

| 경로 | 설명 |
|---|---|
| `GET /` | 정보 패널(HTML) |
| `GET /api/repos` | 최신 리포지토리 묶음 JSON(heat/grade/learnTags/verdict/starDelta 포함), `watchlist` 시드 병합 데이터도 함께 제공 |
| `GET /api/watchlist` | 중점 모니터링 시드 목록 JSON(각 항목의 카테고리, 사람이 쓴 학습 포인트, 실시간 적중 데이터 `live` 포함, 적중하지 않은 경우 `null`) |
| `GET /api/stats` | 가장 최근 라운드의 순찰 메타 정보(시간, 채널별 개수, 오류, 이름 변경 이벤트 `renames`) |
| `GET /api/brief` | 대통령 브리핑 JSON(패널 플로팅 창과 동일한 데이터: 정세, 급상승/인기 TOP3, 사이버 보안/Skill 포커스, 이름 변경 동향, 키워드 인기도, 토픽 트렌드, 중점 모니터링 동향), `brief.push` 전송 상태(`configured: {dm, manualChannel, autoChannels}` 개수와 오늘 각 대상의 결과, 채널 제목/전체 id는 포함하지 않음)도 함께 제공 |
| `POST /api/brief/push` | 대통령 브리핑을 TG 대상(개인 채팅 + 수동 채널 + 자동 등록 채널)으로 수동 전송합니다. Secret `PUSH_KEY`가 필요합니다: 설정되지 않으면 403과 함께 `status: "push_disabled"`를 반환하고, 요청 헤더 `x-push-key`가 없거나 잘못되면 401과 함께 `status: "unauthorized"`를 반환합니다(전송하지 않고 스로틀링도 기록하지 않음). 인증을 통과한 뒤에는 대상별로 6시간 스로틀링을 적용해 스로틀링되지 않은 대상에만 전송하며, 응답에는 `targets`(이번에 전송한 대상 키)와 `skipped`(스로틀링으로 건너뛴 대상 키)가 포함되고, 대상이 없으면 `status: "not_configured"`를 반환합니다 |
| `GET /api/tg/commands` | Bot 명령어 목록 JSON(`setMyCommands`용, 8개) |
| `POST /tg/webhook` | Telegram Webhook 입구(Bot 읽기 전용 명령 + 채널 자동 등록. Secret `TG_WEBHOOK_SECRET`이 필요하며, 설정되지 않으면 404, 키가 잘못되면 403을 반환) |
| `POST /api/refresh` | 순찰을 수동으로 트리거합니다. 30분 이내의 반복 호출은 스로틀링됩니다(`throttled: true` 반환) |
| Cron `scheduled()` | 정기 순찰, 수동 스로틀링을 거치지 않음 |

KV 키: `intel:latest`(최신 데이터), `intel:prev`(이전 라운드 스타 스냅샷, v4부터 id 키 형식), `intel:meta`(순찰 메타 정보), `intel:seedids`(시드 리포지토리 id 매핑), `intel:seedcursor`(시드 신선도 유지 로테이션 커서), `intel:seedlive`(시드 신선도 유지 결과), `intel:topichist`(토픽 트렌드 기록 스냅샷, 최근 56개), `intel:briefpush`(브리핑 매일 전송 상태, v5.3부터 `{date, targets}`로 대상 키별 기록), `intel:pushmanual`(수동 전송 스로틀링, v5.3.1부터 대상별 매핑 `{"dm"|"ch:<chatId>": ts}`, 구 전역 형식은 읽을 때 마이그레이션), `intel:tgchannels`(자동 등록된 채널 표, v5.3 신규).

## 데이터 정직성 안내

- 데이터 출처는 GitHub Search API의 공개 검색 결과뿐이며, 정렬과 수록 기준은 GitHub가 결정합니다. 채널 쿼리는 키워드 규칙이며 GitHub 공식 Trending이 아닙니다.
- **스타 증가분에는 최소 두 라운드의 순찰이 필요합니다**: 첫 라운드에서는 모든 리포지토리의 증가분이 비어 있고, 판정에는 '정보 데이터베이스에 신규 등록'이라고 적힙니다. 두 번째 라운드부터 `+N★`가 나타납니다.
- 미인증 호출 한도는 매우 낮습니다(Search API 약 10회/분, 시간당 할당량도 있음). 라운드당 11회 호출은 문제없지만, 수동 새로고침을 고빈도로 하지 마세요——코드에는 이미 30분 스로틀링이 있습니다.
- 어떤 채널의 가져오기가 실패하면 해당 채널은 패널 티커에서 이상으로 표시되고 이전 라운드의 해당 채널 구 데이터를 그대로 사용하며, 데이터 전체를 지우지 않습니다. 모든 채널이 실패하면 기존 데이터를 덮어쓰지 않습니다.
- 판정, 등급, 학습 포인트는 모두 규칙의 산물이며 오판 가능성이 있습니다(예: 설명에 키워드를 끼워 넣은 리포지토리). 선별을 위한 참고일 뿐이며, '배울 가치가 있다'는 결론을 보장하지 않습니다.
- KV는 최종 일관성 저장소입니다. 순찰이 막 기록을 마친 수십 초 동안 패널이 일시적으로 구 데이터를 읽을 수 있으며, 이는 정상적인 현상입니다.
